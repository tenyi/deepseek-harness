# @deepseek-ai/dsh-fs-e2b

[English](README.md) | 中文

## 概述

`dsh-fs-e2b` 讓 agent 的文件操作在遠程沙箱內運行：agent 可以讀取文件、列出目錄、寫入新文件、覆蓋或編輯現有文件，并獲得準確的元數據——這些操作都發生在其命令運行的同一遠程環境中。它不需要任何配置；掛載它就把文件工作從宿主機器上移走。請與 `dsh-e2b`、`dsh-subprocess-e2b` 一起使用，讓文件與命令共享同一個遠程工作目錄。宿主機器上的文件永遠不會被觸及，模型看到的結果與本地文件結果完全一致。當文件應留在宿主上時，請選擇本地的文件系統包。

<a id="use-this-package"></a>
## 使用本包

當 agent 的文件工作——讀取、寫入、編輯、列出——應在遠程沙箱內而非你的機器上進行時，使用本包。它是 E2B 家族中的文件系統部分：agent 在這里寫入的內容，正是它的命令能在同一個沙箱中讀取的內容。

### 何時選擇

當組合已經使用 E2B 沙箱且希望文件操作在其中運行時，選擇本包。當文件應留在宿主上時，選擇本地文件系統包。這里沒有需要調優的配置。

### 掛載

先加載沙箱所有者，再加載本包；之后文件功能就會作用于沙箱：

```yaml
- name: '@deepseek-ai/dsh-e2b'
- name: '@deepseek-ai/dsh-fs-e2b'
```

掛載它不會復制或鏡像你的本地文件——沙箱的工作目錄從空開始，并隨 agent 的工作逐漸被填充。

### 讀取文件

agent 可以讀取文件的完整內容、流式讀取大文件，或在大小上限內或按字節窗口讀取原始字節。二進制文件與不是有效 UTF-8 文本的文件會被明確拒絕而不是亂碼顯示；超過大小上限的讀取會以指明上限的消息失敗。

### 寫入與編輯文件

agent 可以創建文件、覆蓋文件，或通過替換一段字面量文本（可選地替換所有出現處）來編輯文件，也可以要求僅在文件尚不存在時創建它。一次寫入要么完整落地，要么完全不落地——失敗的寫入絕不會留下不完整的文件。如果文件在 agent 上次讀取之后發生了變化，寫入會被拒絕而不是覆蓋較新的內容，因此兩個進程不會在互不知情的情況下覆蓋彼此的工作。

### 沙箱中的路徑

相對路徑會針對調用方的工作目錄或沙箱共享工作目錄解析，并按其在沙箱中的 POSIX 路徑報告——agent 讀寫的內容與它的命令看到的內容完全一致。

## 理解實現

<details>
<summary>實現細節——點擊展開</summary>

本節解釋提供方背后的設計決策，并指出實現它們的代碼位置；可觀察行為已在[使用本包](#use-this-package)中完整說明。

### 設計理念

- **同一遠程環境。** 路徑與內容都留在沙箱內；宿主工作區永遠不會被復制、掛載或協調。
- **原子發布。** 每次變更都通過同一文件系統 rename 或受防護鏈接提交，返回的版本來自已提交條目，因此提交點之后不會再有可能失敗的元數據請求。
- **嚴格的傳輸分幀。** 規范化路徑與內容以帶 NUL 分幀的 ASCII base64 形式跨越 SDK，因此換行與多字節數據能經受任意解碼邊界。

### 源碼地圖

| 文件 | 職責 |
|---|---|
| [`src/index.ts`](src/index.ts) | 插件入口：`E2BFileSystem` 提供方、規范化、讀取、原子寫入、錯誤映射 |
| — | 不發布運行時不變式配套項；每個操作都直接返回 E2B 控制器的已提交結果，沒有可用于交叉核驗的獨立事件或緩存。 |

### 規范化路徑與傳輸分幀

相對路徑以調用方 `cwd` 或 `ctx.e2b.cwd` 為基準，按照 POSIX 路徑解析；GNU `realpath -mz` 提供規范化目標身份，且不要求最終文件存在；ASCII base64 加嚴格 NUL 分幀會在已解碼的 SDK 傳輸中保留含換行符和多字節字符的路徑。`stat`、不跟隨鏈接的 `lstat` 與穩定的單層目錄列表會把 E2B 元數據投影到 seam；規范化目標公開絕對 POSIX 進程路徑、百分號編碼的 `file:` URI，以及由提供方負責的包含關系檢查。

### 寫入路徑

寫入會創建隨機的同級暫存目錄，在上傳內容前將其 mode 設為 `0700`，并保留現有文件的 POSIX mode；替換操作通過 E2B 的同一文件系統原子重命名發布，帶防護的 `createIfAbsent` 改用 `ln -T` 發布，即使目標位置出現目錄，也能使提交具備原子且不替換的語義。`dsh-version` 擴展屬性與已提交條目的元數據共同構成返回的版本；字面量編輯匹配時會規范化為 LF，并恢復占主導的 CRLF 風格，變更按規范化目標串行執行。提交后的暫存清理失敗絕不會把一次成功的寫入變成失敗。

### 失敗與取消

E2B 的未找到、權限、中止及其他控制器故障會映射到現有 `FsError` 錯誤碼（`FS_NOT_FOUND`、`FS_PERMISSION_DENIED`、`FS_ABORTED`、`FS_IO_ERROR`），文本與字節讀取則增加 `FS_NOT_TEXT` 與 `FS_TOO_LARGE`。取消在 SDK 請求邊界與發布前立即檢查，但信號永遠不會傳入 rename 或受防護鏈接提交，因此取消無法中斷原子發布，也不會把已提交的寫入報告為失敗。

<a id="model-experience"></a>
## 模型體驗

通過 [`dsh-tool-fs`](../../fs/tool-fs/README.zh.md) 間接影響模型；該工具渲染遠程 UTF-8 內容、目錄結果、變更確認與提供方錯誤，而 E2B 身份與傳輸保持內部實現。

#### KV Cache 影響

不會直接失效：請求前綴變更由 `dsh-tool-fs` 負責；E2B 傳輸永遠不會進入請求。

## 已知限制與延期工作

<a id="known-limitations-and-deferred-work"></a>


這些限制說明本提供方何時不合適，或何時需要特別的運維注意。它們是當前包約束，不是待辦事項清單。

- **不提供宿主同步**：空的 E2B cwd 會一直為空，直到工具、命令或外部進程填充它；本地文件既不會上傳，也不會同步回本地。
- **變更協調僅限宿主進程內**：`createIfAbsent` 會保留與發布發生競態的遠程創建者所寫入的文件，但另一個 harness 連接或命令仍可能與替換操作發生競態；版本防護只能檢測 E2B 元數據所體現的變更。
- **讀取會按路徑重新打開規范化目標**：在解析與打開流之間若并發替換遠程路徑，該操作沒有穩定文件句柄提供圍欄；在該 POC 中，沒有已觀察到的產品缺陷能夠證明提供方專用的有界讀取協議值得引入。
- **仍需承擔完整文件變更成本**：覆蓋差異與字面量編輯會把完整文件讀入宿主內存，每項操作也都會產生 E2B 控制器延遲。
- **該 POC 面向 E2B 默認 Linux 鏡像**：它依賴 GNU `realpath`／`base64`／`chmod`、同一文件系統內的 rename、流式讀取與元數據擴展屬性；自定義模板不在該 POC 范圍內。
